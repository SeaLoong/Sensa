# 浏览器验证与截图基线

**简体中文** | [English](e2e.en.md)

E2E 参与自动 CI 和正式发布检查。单元测试与完整普通浏览器比较通过后，工作流才构建发布包并发布。应用与文档站的测试结果分开记录，不能用文档部署成功替代应用比较。[开发与发布](development.md)

## 测试实际覆盖什么？

| 范围 | 实际运行 | 不能证明什么 |
| --- | --- | --- |
| Sensa 应用 | 真实服务、HTTP／WebSocket、浏览器与回环模拟传输 | 不连接真实设备或 VRChat 客户端 |
| 独立参数图解 | 本地六资产、SVG、软件 WebGL2、拖动与回退 | 不是 Unity 生产端或原生 GPU 捕获 |
| 文档站 | 构建产物的导航、双语章节定位与窄屏滚动 | 不代替应用行为或截图检查 |

大量参数用例持续更新 4096 条模拟参数，检查每页最多 100 行、直接跳页、全目录筛选、冻结和同来源详情。其他用例检查实际输入许可、模式、映射保存、断线与失效停止，并核对模拟传输。设备配置始终隔离，不能因测试自动启用用户硬件。

桌面 1280×900、窄屏 390×844 使用固定浏览器环境；320px 另作重排检查。窄视口不是实体手机，模拟输入不是上传后的 Avatar。[测试源码](https://github.com/SeaLoong/Sensa/tree/main/tests/e2e)

## 到哪里看本次结果？

打开对应 Actions 运行的 Job summary，并下载应用的 `e2e-report` 或文档站的 `pages-verification`。`summary.json`／`summary.md` 记录提交、运行次数、套件、截图模式、项目、视口和失败信息。维护[验证记录](e2e-status.md)时，以实际读取的结果为准，不把用例源码更新写成执行通过。

| 结果 | 含义 |
| --- | --- |
| `passed`／`failed` | 实际通过／失败的用例 |
| `expectedFailure`／`flaky` | 预期失败／多次尝试结果不一致，不算干净通过 |
| `skipped` | 明确跳过 |
| `notRun`／`interrupted` | 没有执行／执行中被中断 |
| Runner／Command | 浏览器程序报告的状态／Actions 命令最终状态，两者都要核对 |

没有本次有效报告时，摘要记录未运行和零条已观测用例，不估算尚未加载的用例数。发布比较凭据只接受当前提交、同一次运行、桌面和窄屏完整套件全部通过的普通比较。空运行、过滤／分片、跳过、重试通过和候选模式均不能替代它。

## 截图失败怎样处理？

先查看 expected／actual／diff、trace、服务日志与最后观测值。行为或布局错误应修实现；有意改变的界面，需要审阅图片后更新基线。普通 CI 禁止自动写入基线，缺图也失败。

## 怎样手动更新 E2E？

在 Actions 运行 [`update-e2e.yml`](https://github.com/SeaLoong/Sensa/actions/workflows/update-e2e.yml)。默认 `screenshots` 模式不需要 AI 密钥，基于当前代码运行浏览器并生成候选图片、报告和待审 PR。工作流不直接修改 `main`，也不自动合并。

推送候选分支和创建待审 PR 使用仓库 Actions secret `SENSA_PAT`；PR 事件自动启动普通 CI，候选采集与代理步骤不接收此密钥。[密钥用途与权限](development.md#工作流使用哪些密钥)

选择 `agent` 模式时，还需在仓库 Actions secrets 中配置 `OPENAI_API_KEY`；代理只维护 `tests/e2e/` 中的测试，再运行候选采集。没有该密钥时应使用默认模式，不把未执行的代理步骤写成通过。外部代理可用自身已获授权的 GitHub 身份启动工作流，无需读取或复制 Actions secret。

打开生成的 PR，按语言和视口查看 actual／expected／diff、测试改动及运行结果。只接受有意的界面变化，保留必要行为断言。维护分支会触发普通 CI；普通比较通过和人工审阅完成后，再决定合并。候选采集本身不发布产品，也不能作为普通比较凭据。

只需要报告附件时，仍可手动运行 `e2e.yml` 的 `update_snapshots=true`，下载 `e2e-baselines` 和 `e2e-report`。失败任务的部分截图仅供诊断，不能自动接受。

## 人工和真实环境的边界

按 [V1–V6](ui-quality.md)评估层级、字体、分组、配色、对齐和双语完整性。axe 与键盘检查是可自动检测的子集，保留 incomplete 和未执行项；零违规不是完整 WCAG 认证。历史接受范围见[视觉评审存档](ui-visual-review.md)。

Unity 上传、真实 Contacts／OSC、HMD／桌面编码与机械停止仍需分别验收。测试报告必须说明模拟来源，不能把浏览器或回环结果写成硬件已通过。
