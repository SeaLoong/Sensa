# 输入、计算与输出

**简体中文** | [English](signal-pipeline.en.md)

Sensa 将来源中的数据整理为信号，按需要计算，再发送到设备、应用或录制文件。同一个计算结果可以供多条输出绑定使用，每条绑定分别设置目标、量程和发送节奏。

```text
OSC 参数／定位、手动、脚本、设备反馈
                    ↓
            原始信号与可复用计算
                    ↓
       每条绑定的量程、类型和更新频率
                    ↓
      设备、OSC 参数、网络服务或录制
```

例如，先将两个触碰区域合成为“接触强度”，再分别用于设备振动、DG-LAB 通道和 Avatar 发光。每条输出按自己的范围解释这一结果。[计算信号](computed-signals.md) · [工作台指南](guide.md)

## 选择来源与计算

手动、OSC 和脚本保留各自的快捷输入方式；“组合”让多种来源共同参与输出绑定。先准备并保存设置，再应用所需输入方式，最后启用输入。

| 来源 | 可以读取的内容 | 使用例子 |
| --- | --- | --- |
| OSC 参数 | 明确路径与来源的数值 | 触碰程度、开关或档位 |
| 定位指标 | 已通过模型检查的位置、距离、姿态或速度 | 两个根点间距、局部运动速率 |
| 手动 | 手动轴的当前设置 | 为所有效果提供可随时调整的总强度 |
| 脚本 | 当前脚本轨迹与播放指标 | 基础节奏或动作轨迹 |
| 设备反馈 | 已连接输出提供的状态和读数 | DG-LAB APP 按钮、设备强度或压力读数 |
| 录制回放 | 已载入会话中选定的信号 | 重现一次交互，并调整计算方式 |
| 固定数值／计算信号 | 常量或已保存的具名结果 | 比例系数、多个输出共用的中间计算 |

计算保留原始单位和有效状态。位置、速度与接近值变化率各用自己的量程；每条输出绑定再把最终结果换算为目标需要的范围。单位和坐标框的选择见[定位说明](positioning.md)。

## 添加输出与绑定

在“输出”中添加目标，选择输出方式并填写它内部的连接设置。为目标添加绑定，依次选择来源、输入范围、输出范围和目标参数。保存后，检查实时结果与连接状态，再启用输入。

| 输出方式 | 连接与目标 | 适合的内容 |
| --- | --- | --- |
| TCode 串口／UDP／TCP | 端口或网络地址，以及轴配置 | 位置、旋转、振动和辅助轴 |
| Intiface | Central 地址与设备特征 | 支持的位置或振动功能 |
| OSC 参数 | IP、端口、参数地址和 Float／Int／Bool 类型 | Avatar 参数或其他 OSC 应用 |
| DG-LAB | WebSocket 中继、配对 APP、设备与通道 | 临时强度、波形任务及状态反馈 |
| HTTP JSON／WebSocket JSON | 接收 JSON 的服务地址 | 外部面板、插件或自制服务 |
| MQTT | Broker、端口与主题 | 自动化服务或订阅应用 |
| MIDI CC | 系统 MIDI 输出端口、通道与控制器 | 应用音量、声像或其他 MIDI 控制 |
| 录制 | 文件名称、格式与要记录的信号 | 调试会话、离线分析和重放素材 |

TCode 的绑定目标是十二轴中的一条轴，数值使用 0～1，再由该输出的轴配置设置实际范围和运动方式。Intiface 的绑定目标可选 L0 和该输出配置的振动轴，按设备能力转换为位置或振动指令。

绑定中的输入范围表示原始数值的起点与终点，输出范围表示接收端需要的数值。OSC、网络、MIDI 和动作轴绑定可设置停止值，用于来源失效时结束该绑定的作用；按目标含义选择，例如开关为 false、强度为 0，或状态参数的默认值。关闭输入、停用输出和急停时，动作设备执行设备停止指令。

OSC、网络、MIDI、录制和动作轴绑定提供三种发送方式：“数值变化时发送”适合状态和缓慢变化的读数，可设置最小变化量；“按固定频率发送”适合需要定期更新的目标；“正向触发时发送”在换算后的信号变为正值时交付一次动作。这些绑定可设 1～100 Hz 的发送频率，共用来源的输出可以各自采用合适的节奏。事件按顺序交付，状态发送保留最新数值。需要接收开、关两种状态的目标，使用状态发送方式。DG-LAB 按任务时长自动安排发送与续接，操作见下文。

## 回写 VRChat OSC

添加“OSC 参数”输出，勾选“回写到 VRChat OSC”，使用 VRChat 的接收地址与端口，通常是 `127.0.0.1:9000`。填写当前 Avatar 已配置为可写的参数地址与类型，例如：

| 目标示例 | 类型 | 来源用途 |
| --- | --- | --- |
| `/avatar/parameters/SensaFeedbackIntensity` | Float | 以 0～1 表示效果强度，供 Avatar 发光、颜色或形变动画使用 |
| `/avatar/parameters/SensaFeedbackActive` | Bool | 表示某个效果当前是否生效 |
| `/avatar/parameters/SensaFeedbackMode` | Int | 选择 Avatar 已配置的效果档位 |

Avatar 的 OSC 配置决定输入地址与预期类型，配套的表达参数和动画负责呈现效果。测量参数与反馈参数分别命名，便于读写依赖检查和排查循环。按当前 Avatar 核对目标后，再检查范围与发送节奏。[VRChat 官方 Avatar 参数接口](https://github.com/vrchat-community/osc/blob/main/docs/Avatar-Parameters.md)

Sensa 原有 OSC Hub 继续用于转发收到的消息；OSC 参数输出根据绑定结果生成消息。OGB 心跳则继续维护 Avatar 的参数发布条件。[接收、转发与心跳](guide.md#接收发现与转发)

## 连接 DG-LAB

DG-LAB 输出采用 DG-LAB 4 APP 的 WebSocket V4 接口。选择官方中继或自己部署的 V4 中继，连接后用本地生成的配对二维码或配对链接接入 APP。APP 上报设备后，选择实际设备与 A／B 通道；设备选择同时记录 APP 标识与设备标识，便于区分多个 APP 中的设备。

先保持通道强度上限为 0，完成配对和设备选择，再按需要设置上限。`Intensity` 把绑定结果限制到 0～1，再乘以该通道的用户上限；`Pulse` 发送已配置的波形帧。临时强度与波形分别配置，任务持续时间为 100～1000 ms，持续效果通过短任务续接。

`Intensity` 可选“跟随输入”，由后端按当前强度续接短时任务；“触发一次”在换算结果变为正值时发送一次临时强度任务。`Pulse` 可选“持续播放”，达到 0.5 时按 100 ms 波形帧的当前进度连续续接；“触发一次”在达到 0.5 时发送一次波形任务，回落后可再次触发。COYOTE_030 可选择 Sensa 生成的平稳、渐变和交替基础效果，也可以在高级设置中逐行填写自定义帧。

配对、设备选择和输出启用分步进行。尚未选择设备时保持中继与 APP 配对，保存同一中继的绑定或通道设置也保留连接。连接中断后通过连接按钮重新连接；检查设备、通道和任务状态后，再启用输入。郊狼 3.0 的临时强度与波形绑定分别停止，自定义帧按对应设备协议处理。全局停止会清理待发任务，并向仍连接的目标发送停止操作。反馈数据按设备实际提供的能力作为新输入。

DG-LAB 4 APP、V4 网络协议和郊狼硬件型号分别表示应用、通信与设备版本。可用设备和反馈以 APP 实际上报为准。[官方 DGLAB KIT](https://github.com/dungeonlab-open/dglab-kit/blob/main/README_CN.md) · [官方 WebSocket 中继](https://github.com/dungeonlab-open/dglab-websocket-server/blob/main/README_CN.md)

## 其他应用与 MIDI

HTTP JSON 与 WebSocket JSON 的消息包含 `address`、`value`、`type`、`signalId`、`unit`、`coordinateFrame` 和 `timestampMs`，MQTT 按选定主题发布同类 JSON。接收应用根据配置的地址解释数值。

MIDI 使用操作系统可用的输出端口。在端口列表中刷新并选择目标，将地址填写为 `CC/通道/控制器`：通道为 1～16，控制器为 0～127，发送值也为 0～127。例如，`CC/1/1` 发送第 1 通道的第 1 控制器。Windows、macOS 使用系统 MIDI 服务；Linux 需要 ALSA 及可用的音序器，包括 `/dev/snd/seq`。

## 录制与观察

“录制”输出将选中的信号和输出结果写入会话文件。JSON Lines 适合逐条读取和保留结构化信息，CSV 适合用表格或分析工具查看。为每条绑定选择来源，再填写“记录字段”；这个字段保存为文件中的 `signalId`，留空时使用绑定标识。每个字段分别按绑定的发送节奏记录。

原有 L0 录制继续导出 funscript，适合保存单轴动作轨迹。会话录制用于观察多条信号、计算与输出的关系，两者可以按用途选择。[L0 录制](guide.md#l0-录制)

会话文件写入程序旁的 `recordings/`；用 `SENSA_RECORDINGS_PATH` 可指定其他目录。记录包含相对时间、信号标识、原始值、换算值、有效性、原因、来源和坐标框。每个文件最多 64 MiB、250000 条采样；回放最多读取 64 个信号。记下详情显示的文件名，完成后断开录制输出，使文件完整写入。

展开“录制回放”，点击“刷新录制列表”，从“已录制文件”中选择会话，再点击“载入录制”；也可以直接填写“回放文件名”。载入后保持暂停。选择文件中的信号标识，在“录制回放”输入中填写 `录制输出标识/信号标识`。保存目标绑定，应用组合方式并启用输入，再播放回放。支持暂停和按毫秒跳转；暂停、结束与记录中的无效区间按无效输入呈现。回放读取录制时的原始值，新绑定可以继续应用自己的量程和曲线。

实时预览应沿同一条绑定核对来源、原始值、计算结果和发送目标。设备回报的状态单独展示，便于对照指令与反馈。复杂方案先使用录制或可观察的应用参数检查换算，再接入实际设备。

## 保存与复用整套方案

展开“保存与载入整套方案”，可将轴映射、轴配置、计算信号图和输出设置导出为 JSON，并填写便于辨认的方案名称。轴配置一并保留各轴的范围与处理设置。导入时先打开检查窗口，列出计算、映射和输出数量；应用后替换当前配置中的这些部分。

导入后的输出与输入启用状态关闭。核对目标地址、引用的轴配置、设备选择和来源路径后，再启用需要的输出。脚本文件、当前手动值和外部应用设置由本机环境提供。

## 页面与连接共用

工作台在一条实时连接中复用状态推送和控制请求。同源标签页优先通过 SharedWorker 共用这条连接；共享工作线程无法启动时，支持 BroadcastChannel 与 Web Locks 的浏览器会由一个标签页维护连接，其他标签页共用。各页保留自己的草稿和请求响应。

关闭一个标签页后，其他标签页继续使用共享连接，或由下一持有页接续。页面进入缓存时释放当前订阅，恢复后重新附着。重连只恢复会话与状态读取，控制请求按各自的超时和结果结束。

浏览器无法使用这两种跨页共享方式时，每个标签页使用自己的单例连接。大量标签页的可用数量还取决于服务端会话预算。HTTP 连接池、WebSocket 和服务端会话上限分别管理，多个页面的共享范围以当前浏览器能力为准。

## 配置与启停

浏览页面和编辑草稿保持当前实际状态。保存配置、更换输入方式或替换脚本时，先关闭输入并停止；确认新方案后再启用。急停覆盖所有输出，解除急停后再单独启用输入。

每条绑定根据自己的必需输入判断有效性，相关读数失效时使用该绑定的停止行为。来源和计算恢复后，后端依据当前输入启用状态决定是否继续。设备连接与输入启用分别管理。

实现职责与约定见[架构](architecture.md)和[输入、计算与输出决策](adr/0008-signal-pipeline-and-shared-session.md)。实际自动检查记录见[浏览器验证](e2e-status.md)。
