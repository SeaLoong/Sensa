## CI evidence

The old #10/#11/#12 E2E runs expected HTTP 200 from /api/session while the endpoint returns 204. Main already fixes that assertion. Those failures do not establish incompatibility of these updates. Older green PR runs also predate the current bilingual E2E and image-bridge corrections.

The integration branch starts from current main and runs validation → screenshot-comparison E2E → six native platform tests/builds/smokes before main advances. Main validates again and can publish a prerelease. A manually dispatched branch run does not publish. Consult the exact commit's [Actions results](https://github.com/SeaLoong/Sensa/actions/workflows/ci.yml).

No screenshot baselines are relaxed to accept a dependency regression. No local E2E or physical devices are used. Passing mocks do not certify arbitrary firmware/mechanical behavior.

## Frontend migration requirements

React 19 requires the modern JSX transform; this project's esbuild currently uses classic defaults. #12 only changes package/lock files. A separate migration must enable automatic JSX, review MUI/Emotion/ref behavior and pass complete E2E. The obsolete session assertion is not evidence that React itself fails. [React upgrade guide](https://react.dev/blog/2024/04/25/react-19-upgrade-guide)

MUI 9 raises default browser support to Chrome 117, Firefox 121 and Safari 17, while the project targets Chrome 110, Firefox 115 and Safari 16. It also changes component APIs, keyboard/focus behavior and DOM structure. Define supported browsers, migrate from v5 and review screenshots; installation/compilation alone is insufficient. [MUI 9 upgrade guide](https://mui.com/material-ui/migration/upgrade-to-v9/)

Keep both PRs open with needs-migration rather than disabling future security updates. The production npm audit reported no vulnerabilities at review time; that is neither a permanent guarantee nor a claim that major upgrades lack long-term value.
