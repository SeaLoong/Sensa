## 旧 CI 为什么不能直接作为合并依据

#10、#11、#12 的旧 E2E 日志仍断言 `/api/session` 返回 200，实际接口返回 204。该测试问题已在 main 修复，不能归因于这些升级。其余绿色运行早于当前中英双语 E2E 和图像桥接修复，也不能证明当前集成正确。

本批次先在最新 main 上集成，在分支执行完整 CI：基础检查 → E2E 截图比较 → 六平台测试/构建/冒烟。通过后才推进 main；main 再验证并自动生成预发布。分支手动验证本身不发布。最新结果以对应提交的 [Actions](https://github.com/SeaLoong/Sensa/actions/workflows/ci.yml) 为准。

不更新截图基线来容纳依赖回归，不在本机运行 E2E，不连接真实硬件。测试成功不能证明每种固件或物理机械行为。

## 本轮发现并修正的测试问题

集成验证 [38858242887](https://github.com/SeaLoong/Sensa/actions/runs/38858242887) 暴露了旧 mock 对停止消息的错误假设。Buttplug 5.0.1 的 StopAllDevicesAsync 实际发送 v4 的 StopCmd（不指定 DeviceIndex/FeatureIndex），而旧 mock 仍接受 StopAllDevices，并等待这个旧名字。核对 [NuGet 对应源码](https://github.com/buttplugio/buttplug-csharp/blob/ec8e6ff175e33dd75778cc91c485ec1a24353915/Buttplug/Client/ButtplugClient.cs#L247) 后，mock 改为确认全局 StopCmd，并拒绝旧停止名字；断言同时检查模拟设备已停止、输出卡获得停止确认，以及解除急停不恢复运动。不是删掉失败断言，也不需要改变截图基线。

## 两个前端主版本 PR 的后续条件

React 官方要求现代 JSX transform，而当前 esbuild 配置仍使用默认 classic transform。#12 只改 package/lock 文件，没有迁移构建设置。应在独立迁移中启用自动 JSX、核对 MUI/Emotion/ref 行为，然后通过完整 E2E；不能将旧会话断言失败冒充 React 本身不兼容的证据。[React 升级指南](https://react.dev/blog/2024/04/25/react-19-upgrade-guide)

MUI 9 将默认浏览器基线提高到 Chrome 117、Firefox 121、Safari 17，而当前构建目标仍是 Chrome 110、Firefox 115、Safari 16。还涉及控件 API、键盘/焦点和 DOM 结构变化。应明确浏览器支持范围、完成从现有 v5 的组件迁移并逐张审阅截图；仅 npm 安装和编译通过不足以接收 #6。[MUI 9 升级指南](https://mui.com/material-ui/migration/upgrade-to-v9/)

两个 PR 保留开放并标为 `needs-migration`，不关闭或屏蔽后续安全更新。当前 npm 生产依赖审计未报告漏洞，但这不等于永久安全保证，也不代表主版本升级没有长期价值。
