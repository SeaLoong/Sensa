# Root tracking and sample validity / 根点定位与样本有效性

SPS 四点定位通过 P0–P3 四个距离值计算根点位置，Sample 同时表示当前测量有效且生产端持续运行。Unity 生成器与桌面解算器使用相同的测量点布局。距离保持不变时可复用已有值；持续变化的 Sample 用于判断数据是否仍在更新，因此能配合仅在数值变化时发送的 OSC 参数。各字段分别到达，样本时效与 Avatar 缩放检查共同决定这一组数据能否用于定位。[参数说明](../osc-parameters.md)

SPS four-anchor tracking calculates a root position from four distance values, P0–P3. Sample indicates valid measurements and ongoing producer activity. The Unity generator and desktop solver share one anchor layout. Unchanged distances can reuse their previous values while a changing Sample confirms continued updates, supporting OSC parameters sent only when their values change. Fields arrive separately; sample age and Avatar-scale checks determine whether the set can be used for tracking. [Parameter reference](../osc-parameters.en.md)

Shader 根点捕获使用专用 OSC 路径，接收同一来源的完整十二字段，并通过变化的 Frame 检查画面更新。Point、Handle 与 Pose 分别保留各自的有效期。使用空间映射时，先在设置中启用实验定位，再启用输入；测量失效会停止相应输出。CRC 检查传输内容，Producer ID 区分测量通道，解算残差衡量距离值与模型的吻合程度。实际位置精度通过客户端和设备环境验证。

Shader root capture uses dedicated OSC paths, twelve complete fields from one source, and a changing Frame to check image updates. Point, Handle and Pose keep their own validity windows. To use spatial mappings, enable experimental tracking in settings, then enable input; invalid measurements stop the affected output. CRC checks packet contents, Producer ID distinguishes measurement channels, and solver residuals describe how closely the distances fit the model. Position accuracy is verified in the target client and device environment.

## Coverage and image alignment / 覆盖范围与画面对齐

SPS 四点定位的接收半径为 2，测量点沿各坐标轴偏移 ±0.35，点间距约 0.990，均按 AvatarRootLocal 的制作局部单位定义。只有制作时与运行时的 Avatar 根缩放均为 1，这些数值才直接等于世界米。SDK 的 3 m 世界半径上限仍限制可用根缩放。SPS 四点定位的有效区域须同时满足全部距离测量、未饱和与解算边界；覆盖显示按四个接收器的共同有效区域绘制。SPS 四点定位与 Shader 的坐标边界均为相对中心 (0, 1, 0) 各轴 ±2 个 AvatarRootLocal 单位；Shader 单独展示其编码边界。Contact 直接定位的米制坐标与单接收器覆盖按下节的 AvatarRootMeters 契约解释。

SPS four-anchor tracking uses a receiver radius of 2, measurement-point offsets of ±0.35 along each coordinate axis, and approximately 0.990 between points, all in AvatarRootLocal authored units. These values equal world metres directly only when authored and runtime Avatar-root scales are both one. The SDK's 3 m world-radius limit still constrains usable root scaling. SPS four-anchor tracking coverage requires every distance measurement, unsaturated values and the reconstruction bounds; coverage displays show the common usable region of all four Receivers. SPS four-anchor tracking and Shader coordinates allow ±2 AvatarRootLocal units per axis relative to (0, 1, 0), with Shader encoding bounds shown separately. Contact direct tracking's metre-based coordinates and single-Receiver coverage follow the AvatarRootMeters contract below.

原生 Shader 图块采用 QR Code Model 2、Version 4、H 纠错等级。33×33 格主体外每边留 8 格白色，共 49×49 格：4 格标准静区与 4 格位移余量。三点蒙皮三角形在同一几何阶段提供位置、X/Z 两轴向量及 Avatar 世界均匀缩放，形成 32 字节包。Byte mode 编码后分成四组 RS(25,9)，每组支持 `2e+s≤16`，交织码字并从 8 种掩码中评分选择，再检查整包 CRC32。注册区域至少 196×196 物理像素；桥在所选区域内定位图块并采样。Frame 检查重复与冻结，端到端时间延迟单独测量。独立诊断 PNG 保持五字段与独立布局。[编码契约](../shader-capture-research.md)

The native Shader tile uses QR Code Model 2, Version 4, error correction H. Its 33×33-module symbol has eight white modules per side, making 49×49: four for the standard quiet zone and four for movement. A three-point skinned triangle supplies position, X/Z-axis vectors and uniform Avatar world scale in one geometry stage, forming a 32-byte packet. Byte-mode framing feeds four RS(25,9) blocks, each supporting `2e+s≤16`; codewords are interleaved and scored across eight masks, followed by whole-packet CRC32 verification. The registered region needs at least 196×196 physical pixels; the bridge locates and samples the symbol inside that region. Frame detects duplicates and freezing; end-to-end time latency is measured separately. Diagnostic PNGs retain five fields and a separate layout. [Encoding contract](../shader-capture-research.en.md)

## Native Contact reports / 原生 Contact 报告

SDK 3.10.6-beta.2 的高级 Proximity 报告作为独立方案接入，显示名称为 **Contact 直接定位（SDK Beta）**；SPS 根点方案显示为 **SPS 四点定位**，保留 `Sensa/SPS/<id>/{P0,P1,P2,P3,Sample}` 与全部解算条件。Automatic SPS Setup 默认选择 SPS 四点定位，Contact 方式明确选择且要求 SDK 能力可用。每个作者使用独立碰撞通道、一个跟随所选自身根点的球形 Sender 和一个 Avatar 根零偏移 Receiver，可使用明确的 SPS、Sensa 或原生 Contact 根点。

高级报告保留发送形状中点相对接收形状中点的米制位移，按接收形状轴旋转；Sensa 布置将其命名为 **AvatarRootMeters**，与按制作尺度解释的 AvatarRootLocal 分别处理。接触点相对速度保留 SDK 的角运动项；ProximitySpeed 单位为接近值／秒。公开路径为 `Sensa/Contact/<id>/` 下十个原生报告字段，加上实际世界半径 Radius 和活动 Sample，共十二字段。Sample 约每 50 ms 循环 n/32，变化年龄上限 1000 ms，停用为零；Radius 随 ScaleFactor 更新并保留 3 m 半径门控。原生报告未提供时钟、序号或稳定 Sender 标识。SensaPoint 对位置与速度共用现有校准、启用和失效停止；多点姿态留待后续。[Beta 依据与操作](../contact-sdk.md)

The advanced Proximity reports in SDK 3.10.6-beta.2 form a separate route named **Contact direct tracking (SDK Beta)**. The existing SPS root route is named **SPS four-anchor tracking** and retains `Sensa/SPS/<id>/{P0,P1,P2,P3,Sample}` and its complete reconstruction rules. Automatic SPS Setup defaults to SPS four-anchor tracking; Contact is explicitly selected and requires the SDK capability. Each author uses a unique collision channel, one spherical Sender following its selected own root, and one zero-offset Avatar-root Receiver. Explicit SPS, Sensa and native Contact roots are supported.

Native position retains metre-based Sender-shape-midpoint displacement relative to the Receiver-shape midpoint, rotated into Receiver shape axes. Sensa calls this frame **AvatarRootMeters**, distinct from authored-unit AvatarRootLocal. Relative contact-point velocity retains the SDK's angular-motion terms; ProximitySpeed uses proximity units per second. `Sensa/Contact/<id>/` publishes ten native report fields plus actual world Radius and activity Sample, twelve fields in total. Sample cycles through n/32 nominally every 50 ms, has a maximum 1000 ms change age and is zero while inactive. Radius follows ScaleFactor with the 3 m guard. Native reports have no clock, sequence or stable Sender identifier. Position and velocity share SensaPoint calibration, activation and invalidity stops; multi-point orientation remains future work. [Beta evidence and operation](../contact-sdk.en.md)
