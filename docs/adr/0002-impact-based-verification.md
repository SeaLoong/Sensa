# Impact-based verification and preview gates / 按影响验证与预发布门槛

同一个保守路径计划选择受影响检查；“文档或纯测试不发布”仅适用于没有未完成产品验证的情况。仅比较当前 push 差异会漏掉“产品 CI 失败后只修测试”的候选，因此 main 普通推送还必须自动继承或恢复负责产品验证的执行（owner），不要求提交消息标记或手工 override。失败后的测试修复在当前提交补齐必要产品检查、全量 E2E、原生构建／隔离冒烟及通过门槛后的预发布。

选择轻量 artifact 保留验证意图与真正 owner，再核对 owner 必要 jobs 的真实结果；artifact 本身和后续文档工作流自己的 success 都不能证明产品通过。docs-only 遇到 owner 仍运行时继承记录，不重复必要产品链；缺失、未知、读取失败或 skipped 的必要结果按未完成保守处理。这个额外证据核对用于避免丢失失败产品验证，同时保留正常文档／测试变更的增量成本。路径与恢复决策见 [ci-plan.py](https://github.com/SeaLoong/Sensa/blob/main/scripts/ci-plan.py)，只读执行证据 adapter 见 [ci_evidence.py](https://github.com/SeaLoong/Sensa/blob/main/scripts/ci_evidence.py)。

本地验证仍只读取工作区差异与内容 receipt，不访问 GitHub，也不运行浏览器 E2E、完整进程 smoke 或截图。成功 receipt 按相关源码、命令及工具链保存，相关变化或失败后失效。CI 预发布必须由同一候选 SHA 的全量 E2E 比较及必要产品链证明；仅保留最近十个已公开预发布，稳定版、草稿与 Git tag 保留。

One conservative path plan selects affected checks. “Documentation/test-only changes do not publish” applies only when no product verification is outstanding. Comparing only the current push loses candidates whose product CI failed before a test-only fix. Ordinary main pushes therefore automatically inherit or recover the responsible product run (owner), without commit-message markers or manual overrides. A subsequent test fix completes necessary product checks, full E2E, native builds/isolated smoke and gated prerelease publication for the current commit.

A small artifact preserves intent and the actual owner; required owner jobs must then be checked against their real results. Neither the artifact nor a successor documentation workflow's success proves product verification. Docs-only pushes inherit a still-running owner's record without duplicating necessary product CI. Missing, unknown or unreadable evidence and skipped required results are conservatively unfinished. This extra evidence check prevents failed product verification from disappearing while retaining incremental costs for ordinary documentation/tests. See [ci-plan.py](https://github.com/SeaLoong/Sensa/blob/main/scripts/ci-plan.py) for path/recovery policy and [ci_evidence.py](https://github.com/SeaLoong/Sensa/blob/main/scripts/ci_evidence.py) for the read-only execution-evidence adapter.

Local verification still reads only working-tree differences and content receipts. It does not access GitHub or run browser E2E, full-process smoke or screenshots. Successful receipts are keyed by relevant sources, commands and toolchain, invalidated by changes or failure. CI preview publication requires full E2E comparison and the necessary product chain for the same candidate SHA. Retain the ten newest published prereleases; preserve stable releases, drafts and Git tags.
