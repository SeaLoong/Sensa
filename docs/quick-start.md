# 首次使用

**简体中文** | [English](quick-start.en.md)

第一次使用时，先用一条简单流程确认“来源数值 → 输出结果”。可以从手动数值录成 funscript 开始，再加入设备、OSC 参数或其他应用。完整配置见[输入、计算与输出](signal-pipeline.md)；VRChat 用户也可先打开[参数图解](https://sealoong.github.io/Sensa/parameter-geometry.html?lang=zh-CN)了解测量含义。

## 1. 启动

从 [Releases](https://github.com/SeaLoong/Sensa/releases)下载对应系统与 CPU 的包，解压运行 Sensa，打开 `http://127.0.0.1:5086`。默认配置位于程序旁 `config.json`；用 `SENSA_CONFIG_PATH` 可指定另一文件。初次测试可用 `SENSA_CONFIG_PATH` 指向单独的配置文件，避免误用之前保存的设备地址。

界面按 URL、已保存选择、系统语言顺序自动识别，也可手动切换。[语言规则](languages.md)

## 2. 配置输出

在“流程”或“控制”添加输出。“输出”是接收 Sensa 结果的设备、应用或录制文件；先选择方式，再在该输出的“输入到输出的连接”中选择来源、目标和量程。简单流程可直接选“手动 → L0”；需要融合或处理时，再选择计算信号。

| 类型 | 需要确认 |
| --- | --- |
| TCode 串口 | 正确端口；115200、8N1；关闭其他占用端口的程序 |
| TCode UDP／TCP | 真实目标地址、端口和传输类型；UDP 没有执行确认 |
| Intiface | 先启动已有 Central，再填服务地址；新输出默认不管理引擎 |
| Intiface 振动 | 来源默认 V0；可选 V1／V2，只有明确选 L0 才将深度转为强度 |
| OSC 参数 | 目标 IP／端口、可写参数地址和 Float／Int／Bool 类型；回写 VRChat 选项可准备常用接收目标 |
| DG-LAB | 中继连接、DG-LAB 4 APP 配对、实际设备／通道与用户上限 |
| MIDI CC | 可用的系统输出端口、`CC/通道/控制器` 地址与 0～127 量程 |
| 录制 | 默认 Funscript；轨道名称可用 `L0`，来源选择“手动 → L0”，输入／输出范围均为 0～1 |
| HTTP JSON／WebSocket JSON | 接收服务的 URL、目标路径与数值类型 |
| MQTT | Broker 地址／端口与发布主题，以及选定的信号绑定 |

TCode 输出先在“设置”中编辑轴配置，缩小移动范围、降低速度，必要时反向；保存输出时选择这套轴配置。Intiface 的范围、速度限制和停止方式由设备／Central 提供，先确认这些设置，再用手动小目标测试。

保存后启用该输出，确认连接状态。可以添加多个输出，分别使用同一来源或不同来源。界面显示最近发送的目标值；使用动作设备时，结合实际移动检查方向和行程。

## 3. 启用输入并检查结果

在“控制”选择“手动”，点击“应用输入方式”，再启用输入。调整 L0 并“发送一次”，观察绑定的原始值与换算结果。录制输出会把数值写入轨道；关闭输入后，完成的片段可下载或载入脚本播放器。

使用动作设备时，以小幅目标确认方向、行程和停止。“连续发送”持续发送设置的目标值。急停会关闭输入；解除后，准备好再启用。

输入已经启用时，新连接可能立即接收当前有效目标，因此应在连接前核对输入状态。配置变更、模式变更和脚本替换都会关闭输入，准备好后重新启用。

## 4. 选择来源并添加计算

- **OSC**：应用 OSC，核对默认监听 `127.0.0.1:9001` 和实际来源，在参数页观察真实地址。选择[五个模板](presets.md)之一，检查输入范围及允许动作的条件（门控），保存后再启用输入。OGB 参数可能需要接收设置中的显式启用心跳：心跳发往 VRChat，通常使用 9000；Sensa 接收参数使用 9001。
- **脚本**：导入有效 funscript，检查 L0 时间线、倍速及循环。应用 Script、启用输入后播放。暂停停止自动帧；已启用 Script 时，显式定位／步进仍能发送目标。Stop 将播放游标重置到开头；需要停止设备时使用急停。
- **Contact 直接定位（SDK Beta）**：按 [Contact 设置](contact-sdk.md)安装受支持的 Beta SDK，并构建专用自身根点 Sender／Receiver。检查 `Sensa/Contact/<id>/…`；局部动作校准 X／Y／Z／Distance，运动强弱校准速度／Speed／ProximitySpeed。保存后允许实验空间输入并启用 OSC 输入。
- **实验根点**：先按[方案指南](usage-scenarios.md)设置 Avatar 测量组件或桌面图块读取程序。确认面板显示正确对象且坐标有效，再分别记录动作起点和终点，把它们对应到输出的 0% 和 100%，保存映射。最后允许实验空间输入并启用输入。

- **组合**：在计算和输出绑定中选择来源，例如将 OSC 触碰值乘以手动总强度。保存设置，应用组合方式，再启用输入。[设置](signal-pipeline.md)

需要加权、平滑或触发时，打开“流程 → 新增计算信号”，设置运算与输入，再“保存计算与映射”。在各输出的连接中引用这个计算，即可分别发送到设备、OSC 参数、DG-LAB 或录制。每个输出保持自己的量程和目标。[一项结果连接多个输出](signal-pipeline.md#同一个结果连接多个输出)

不同参数表达不同含义：OGB 通常提供接近程度或深度估算；SPS 四点定位与 Shader 提供所选根点相对 Avatar 的三维位置，Contact 直接定位提供米制位置和相对速度。[定位说明](positioning.md)

## 5. 保存录制与整套方案

录制输出默认按绑定保存独立 funscript 轨道，完成片段后可下载、载入脚本播放器，或通过“录制回放”重新参与计算。高级诊断可选 JSON Lines／CSV；L0 录制提供当前主轴的快捷导出。[录制与回放](signal-pipeline.md#录制与观察)

在“流程”展开“保存与载入整套方案”，一起导出计算、轴映射、轴配置和输出；导入时先查看预览，再应用。浏览器支持时，同源多个标签页会自动共用实时连接，各页保留独立草稿。[整套方案与页面连接](signal-pipeline.md#保存与复用整套方案)

出现问题先关闭输入，再依次核对实际模式、来源、映射、门控与日志，定位原因后恢复。[完整操作](guide.md) · [功能参考](features.md) · [首页](../README.zh-CN.md)
