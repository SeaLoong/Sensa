# Sensa terminology / Sensa 术语

Sensa processes input signals and routes results to devices, applications and recording files. These definitions explain terms used in its interface, documentation and code. / Sensa 处理输入信号，并将结果送到设备、应用与录制文件。以下定义说明界面、文档与代码中的常用词，方便对应配置和运行结果。

| Term / 术语 | Definition / 定义 |
| --- | --- |
| **Motion target / 动作目标** | The normalized position or intensity Sensa intends to send to an output. Check physical movement on the device itself. / Sensa 准备发给输出的位置或强度，通常用 0～1 表示；实际移动情况通过观察设备确认。 |
| **Input mode / 输入模式** | The applied Manual, OSC, Script or Combined mode. Quick modes use a single input workflow; Combined lets configured sources contribute together. Tabs inspect and prepare settings. / 当前已应用的手动、OSC、脚本或组合方式。快捷模式使用对应输入流程，组合方式允许已配置来源共同参与；页签用于查看和准备设置。 |
| **Input activation / 输入启用** | The switch that lets the applied input drive outputs. Configuration, mode or script changes turn it off; enable it again when ready. / 允许当前输入驱动输出的开关。配置、模式或脚本变更后会关闭，准备好再启用。 |
| **Emergency stop / 紧急停止** | A stop state that closes input and stays active until cleared. After clearing it, enable input separately when ready. / 立即关闭输入并保持的停止状态。先解除急停，准备好后再单独启用输入。 |
| **Output / 输出** | A named device, application or recording destination with its own settings and enabled state. Input activation controls delivery. / 具有名称、配置和独立启用状态的设备、应用或录制目标；输入启用状态决定是否向它交付结果。 |
| **Axis profile / 轴配置** | A reusable set of axis ranges, limits, directions and motion settings, selected when configuring a TCode output. / 可重复使用的轴范围、限位、方向和运动设置，配置 TCode 输出时选择使用。 |
| **Draft / 草稿** | Configuration edits in the browser waiting to be saved. Save successfully to apply the configuration to the running service. / 浏览器中等待保存的配置改动，保存成功后应用到运行服务。 |
| **OSC source / OSC 来源** | The transport/source identity used to keep incoming values and their arrival/disconnection state separate. Contact Sender identity requires its own verification. / 用于分别记录参数值及到达、断线状态的传输来源；Contact Sender 的身份另行核对。 |
| **Computed signal / 计算信号** | A named result processing OSC, tracking, manual, script, feedback, constant or computed inputs. It retains provenance, sample age and validity and can feed several bindings. / 处理 OSC、定位、手动、脚本、反馈、常量或其他计算输入的具名结果，保留来源、样本时效和有效性，可供多条绑定复用。 |
| **Output binding / 输出绑定** | A source-to-destination connection with its own conversion, type, range and sending schedule. / 从来源到目标的连接，分别设置换算、类型、量程和发送节奏。 |
| **Protocol / 协议** | The meaning and encoding of messages, such as OSC or DG-LAB V4. / 消息的含义和编码规则，例如 OSC 或 DG-LAB V4。 |
| **Transport / 传输** | The connection and delivery mechanism used by a protocol, such as UDP, HTTP or WebSocket. / 协议使用的连接与交付方式，例如 UDP、HTTP 或 WebSocket。 |
| **Session recording / 会话录制** | Selected signals and output results recorded as JSON Lines or CSV, with timestamps for inspection and replay material. / 将选定信号和输出结果按时间写入 JSON Lines 或 CSV，供检查与重放素材使用。 |
| **Shared browser session / 浏览器共享会话** | A realtime backend session shared by same-origin tabs through SharedWorker, or a Web Locks owner using BroadcastChannel, with per-tab request correlation and drafts. / 同源标签页通过 SharedWorker，或由 Web Locks 确定连接归属并用 BroadcastChannel 传递消息，共用实时后端会话；各页保留独立请求关联和草稿。 |
| **Spatial rig / 空间测量组** | Markers interpreted in the same local coordinate frame. Check their target identity and sampling synchronization separately. / 使用同一局部坐标系解释的一组标记，目标身份和采样同步情况分别检查。 |
| **Avatar-root coordinates / Avatar 根局部坐标** | A position measured relative to the selected Avatar root, using its authored local scale. Moving or rotating the whole Avatar preserves this relative position. / 以选定的 Avatar 根为参照、按制作时的局部尺度表示的位置。整个 Avatar 一起移动或转身时，该相对位置保持不变。 |
| **Avatar-root metre coordinates / Avatar 根米制坐标** | AvatarRootMeters places the origin at the Avatar root and follows its rotated axes while retaining physical metre units. Contact direct tracking uses this frame; scale changes physical displacement. / AvatarRootMeters 以 Avatar 根为原点、各轴随根旋转，保留物理米单位。Contact 直接定位使用此坐标框，缩放会改变物理位移。 |
| **Avatar authoring component / Avatar 作者组件** | A serialized Unity component that stores build settings and implements SDK IEditorOnly; Sensa consumes and removes it while retaining generated native components. / 保存构建设置并实现 SDK IEditorOnly 的 Unity 组件；Sensa 读取后移除该脚本，保留生成的原生组件。 |
| **Build copy / 构建副本** | The Avatar hierarchy processed for a build or processed preview, where generators create native output while the source scene remains editable. / 构建或处理后预览使用的 Avatar 层级；生成器在其中创建原生输出，源场景保持可编辑。 |
| **SPS four-anchor tracking / SPS 四点定位** | A route for locating SPS Socket/Plug roots from four fixed proximity measurements. Explicit Transform, Sensa and native Contact targets use the same root protocol. Its public contract remains `Sensa/SPS/<id>/{P0,P1,P2,P3,Sample}` in AvatarRootLocal. / 通过四个固定接近测量定位 SPS Socket／Plug 根点的方案；明确的 Transform、Sensa 与原生 Contact 目标沿用同一根点协议。公开契约仍为 AvatarRootLocal 下的 `Sensa/SPS/<id>/{P0,P1,P2,P3,Sample}`。 |
| **Contact direct tracking (SDK Beta) / Contact 直接定位（SDK Beta）** | One dedicated own-root Sender and one Receiver use advanced SDK Proximity reports for midpoint position and relative contact-point velocity. Sensa adds Radius and activity Sample under `Sensa/Contact/<id>/`. / 一个专用自身根点 Sender 与一个 Receiver，通过 SDK 高级 Proximity 报告提供中点位置和接触点相对速度；Sensa 在 `Sensa/Contact/<id>/` 下补充 Radius 与活动 Sample。 |
| **Relative contact-point velocity / 接触点相对速度** | Sender velocity relative to the Receiver near the contact point, including angular-motion terms, in Receiver axes and m/s. / Sender 相对 Receiver 在近似接触点处的速度，包含角运动项，按 Receiver 坐标轴表示，单位 m/s。 |
| **Proximity speed / 接近值变化率** | Signed rate of Proximity change per second, published as `Proximity_ProximitySpeed`; calibrate it separately from metre-per-second velocity. / 每秒 Proximity 的带符号变化量，参数为 `Proximity_ProximitySpeed`，与 m/s 速度分别校准。 |
| **Dedicated root marker / 专用根标记** | A marker with a known radius, following the selected root center and publishing through its own measurement channel. / 半径已知、跟随选定根点中心、使用独立测量通道的标记。 |
| **Receiver radius / 接收半径** | Distance from one Contact receiver’s center to its spherical boundary. Combine the required receivers’ usable regions to determine the measurement array's common coverage. / 单个 Contact 接收器中心到球形边界的距离。整组覆盖范围由各必需接收器的有效区域共同决定。 |
| **Anchor axis offset / 测量点各轴偏移** | An anchor’s separate X/Y/Z displacements from the array center. Its straight-line distance is the length of that three-component vector. / 测量点相对布局中心在 X／Y／Z 三个方向上的偏移。到中心的直线距离由这三个分量合成。 |
| **Common measurable region / 共同可测区域** | Positions where every required receiver provides an unsaturated distance measurement and reconstruction stays within bounds. Sampling freshness is checked separately. / 所有必需接收器都能提供未饱和距离测量、且解算结果处于边界内的位置区域；采样新鲜度另行检查。 |
| **Sampling activity / 采样活动** | An indication that the producer continues publishing. Sensor freshness, simultaneous sampling and target identity require separate checks. / 表示生产端仍在持续发布。传感器新鲜度、同一时刻采样和目标身份分别检查。 |
| **Native root capture / 原生根点捕获** | Avatar render components encode a selected root position, and a desktop reader decodes the chosen screen region. The result describes that root position. / Avatar 渲染组件将选定根点的位置编码，桌面读取程序再解码指定屏幕区域，得到该根点的位置。 |
| **Model gate / 模型门控** | The parameter explorer's simulated validity and motion conditions. Runtime length estimation, mapping and device output are evaluated in Sensa itself. / 参数图解中模拟的有效性与动作条件。运行时估长、映射和设备输出在 Sensa 中检查。 |
| **Preview release / 预发布** | A downloadable development snapshot in Releases. Use VPM for published stable Unity packages. / Releases 中可下载的开发快照；通过 VPM 安装的是已发布的 Unity 正式版。 |
| **Presentation locale / 呈现语言** | The language used for interface and documentation text. Protocol identifiers and numeric formats follow their fixed technical conventions. / 界面与文档文字使用的语言；协议标识和数值格式遵循固定的技术约定。 |

Use “command target” for outgoing motion values, “connected” for transport status, “Avatar-root coordinates” for AvatarRootLocal, “Avatar-root metre coordinates” for AvatarRootMeters, and “root capture” for encoded root measurements. Use “SPS four-anchor tracking” and “Contact direct tracking (SDK Beta)” as the root-route display names. / 发出的动作值称为“命令目标”，传输状态称为“已连接”，AvatarRootLocal 称为“Avatar 根局部坐标”，AvatarRootMeters 称为“Avatar 根米制坐标”，根点编码测量称为“根点捕获”。根点方案的显示名称使用“SPS 四点定位”和“Contact 直接定位（SDK Beta）”。
